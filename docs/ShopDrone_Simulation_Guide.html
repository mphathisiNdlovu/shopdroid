🎯 Assignment Decoding: What are we doing here?

Your group created a Software Requirements Specification (SRS) for ShopDrone: an autonomous flying multi-rotor system that transports groceries and essential items to rural Zimbabwean homes (e.g. Matobo Ward 4), bypassing washed-out roads and rivers.

The assignment requires every individual in the project team to move beyond paper requirements by building a working 3D simulation prototype using Gazebo (the physics simulator) and ROS 2 (the robotic operating system middleware), enhanced through vibe coding (AI pair programming).

💡 Traceability to Your Proposal

Every piece of software in this simulation directly satisfies a section of your group's proposal:

  • Section 4.6 (Drone Delivery & Flight): Autonomous flight from Hub -> Waypoint Climb -> Cruise at 15m -> Landing -> Return to Hub.
  • Section 4.6 & 5.1 (Obstacle Detection): Forward Lidar range detection with 3-second emergency hover and collision avoidance.
  • Section 4.8 (Safe Delivery Confirmation): Lockable cargo box requiring customer 4-digit One-Time PIN (OTP) with 3-strike tamper lockdown.
  • Section 4.9 (Monitoring & Maintenance): Real-time GPS coordinates, battery discharge model, and low-battery (25%) automated Return-to-Hub failsafe.

⚠️ Linux Mint Specific Gotcha

Linux Mint's codename is xia, but ROS 2 APT packages are indexed under Ubuntu's codename noble. If you use standard Ubuntu instructions with $(lsb_release -cs), it will fail. Our installer handles this automatically by setting TARGET_CODENAME="noble"!

📂 Step 2: Creating and Building the ROS 2 Workspace

ROS 2 uses Colcon to build workspaces. The workspace directory is located at: /home/mphatic/Desktop/group project gazebo/ros2_ws.

Build Commands

Terminal 
cd "/home/mphatic/Desktop/group project gazebo/ros2_ws"

# Source ROS 2 system libraries
source /opt/ros/jazzy/setup.bash

# Build the workspace
colcon build --symlink-install

# Source your workspace environment
source install/setup.bash
💡 Why --symlink-install?

The --symlink-install flag allows you to edit Python files (like flight_controller.py) and run them immediately without having to run colcon build every single time!

⚙️ Step 3: DROID Subsystem Components

Here is how the autonomous delivery logic is implemented across our Python nodes:

1. Autonomous Flight State Machine (flight_controller.py)

Moves through 10 distinct operational states:

State Transitions
IDLE (At Hub) 
  ↳ PRE_FLIGHT_CHECK (GPS locked, battery > 50%)
    ↳ TAKEOFF (Climb vertically to 15m cruise height)
      ↳ EN_ROUTE (Forward flight at 12 m/s toward Matobo)
        ↳ [OBSTACLE_AVOID] (If Lidar detects obstruction < 3m)
          ↳ LANDING (Precision descent to customer pad)
            ↳ AWAITING_OTP (Drone landed, waiting for customer PIN)
              ↳ DELIVERY_COMPLETE (Box unlocked, payload retrieved)
                ↳ RETURN_TO_HUB (Climb and return flight to base)
                  ↳ LANDED_AT_HUB (Solar dock engaged, order closed)

2. Electronic OTP Cargo Box (cargo_lock.py)

Implements SRS Section 4.8. The box only unlocks when the customer enters 4921 on the drone keypad. If 3 consecutive incorrect codes are entered, the system locks out and fires a security alert to the shop operator.

3. Battery Monitor & Failsafe (battery_monitor.py)

Implements SRS Section 4.6 & 4.9. Continuously measures remaining power. If battery drops to 25%, it overrides manual commands and forces an autonomous Return-to-Hub (RTH).

Prompt 1: Adding GPS Waypoint Navigation

Prompt for Google AI Studio 
I am building a ROS 2 Jazzy and Gazebo Harmonic simulation for an autonomous delivery drone in rural Zimbabwe called 'ShopDrone'.
Write a Python ROS 2 node 'waypoint_navigator.py' using rclpy and geometry_msgs/Twist that:
1. Subscribes to /shopdrone/gps/fix (sensor_msgs/NavSatFix) and /odom (nav_msgs/Odometry).
2. Computes the Haversine distance and bearing from the current GPS location to target waypoint: Latitude -20.553200, Longitude 28.514000.
3. Publishes linear and angular velocity to /cmd_vel to steer toward the target.
4. Triggers an arrival event when distance is under 1.5 meters.
Include full error handling and clean comments.
